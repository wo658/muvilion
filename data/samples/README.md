## Opening as projects

`samples.json` is the only sample list. Selecting the Seongsu pop-up (1) or KINTEX (1) project on the start screen copies the included originals, prepares the specified pages as images, and then Meta Model (Muse) reads walls, text and scale evidence live. Real-size evidence comes from the Seongsu pop-up scale bar and the KINTEX dimension lines. Each drawing is saved as an independent workspace and switched from the header. If any original is missing, that bundle is not offered, and if extraction fails no partial project is created. Existing user projects are not changed.

For every drawing, Next.js prepares the original pages as images, and if an API key is present Meta Model reads walls and text. Python, OpenCV and vector-line extraction are not used. Without a key only the original preview is provided and the user confirms real dimensions. The `rasterPdf` branch has been removed.

The plans were independently authored on 2026-10-31 with reference to official service introductions (Seongsu pop-up on 2026-11-03). The Seongsu pop-up space is also fictional, and because brand material is present, creating a new project makes Muse produce the first interior automatically (ADR-0012). These are not official Meta events, commissions or partnerships, nor official brand guidelines. No new external logos, photos or page text are bundled. For Threads' text and public-conversation character see the [official introduction](https://about.fb.com/news/2023/07/introducing-threads-new-app-text-sharing/), and for the current domain the [threads.com move announcement](https://about.fb.com/news/2025/04/new-features-threads-web-experience/).

The `sources` in `samples.json` are the canonical briefs and brand material. A brief contains the space program, furniture and facility quantities for design practice, the experience flow, per-drawing use and example design requests. When a new project is created the text is stored in SQLite as a UTF-8 `.txt` original, so it is also included in project exports. Brand URLs are bookmarks; no web pages are fetched at creation. Only the supplied descriptions and plans serve as model reference material.

Drawing reading calls Meta Model for real when a key is present; without a key only the original preview is shown. Mock simulation or live VR/AI experience results are not pre-filled. Design results are provided only through the recordings below. Plan quantities and operating direction are assumptions; scale, usable area, facility connections and safety conditions must be checked before real design. Existing SQLite projects are not overwritten. The latest material applies when a new sample project is created from the start screen.

## Recorded Muse results (2026-11-04)

Both samples include a recording (`<id>/recorded.json`, `recorded` in `samples.json`) containing the completed design and planning document. Choosing a sample installs this result as a new project without calling the model and opens the planning document with it. The project can be edited exactly like any other project. The start screen and project notice indicate a recorded Muse result, and it is not presented as freshly computed. Choosing "Design from scratch with Muse" actually runs drawing reading and automatic design.

| Sample | Design | Planning document |
|---|---|---|
| Seongsu pop-up | 21 zones, 98 installations, 4 wall graphics | 6 zone cards, 7 actual 3D screen photos |
| KINTEX | 40 × 30 m area inside 1B, 20 zones, 144 installations | 8 zone cards, 9 actual 3D screen photos |

Recording method: on a development server started with `NEXT_PUBLIC_MUSE_RECORDING_BUDGET=1` (25 minutes per run), the sample was created, Muse designed it automatically, and then chat requests asked for finishing improvements and a planning document. For KINTEX, as the brief specifies, the floor boundary was set to 40 × 30 m inside 1B and the scale was confirmed against the 171 m Hall 1 width (drawing 233.6 × 178.4 m). No person moved objects directly. Muse's own usability review (seat access, aisle connections) was saved with some items outstanding, shown under the project's "Items to review". The recording is in project export format, and the drawing originals reference the sample files in the same folder by path. To re-record, run `node web/scripts/record-sample.mjs <export.json> <sample-id> [note]` with an exported JSON.
