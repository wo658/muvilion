# 도면의 벽과 축척 근거는 Muse가 페이지 이미지에서 찾는다

현재 목표는 실측 재현이 아니라 데모 수준의 빠른 3D 콘셉트다. 엔진이 추출한 미분류 선을 사용자가 일일이 분류하는 대신, PDF와 이미지 도면은 엔진이 페이지를 렌더링한 뒤 Muse가 이미지와 텍스트 위치를 보고 벽 선분을 직접 제안한다. 업로드와 샘플 프로젝트 모두 같은 경로를 쓴다. 실제 크기로 만들기 위해 Muse는 도면에 적힌 축척 근거의 위치와 값을 함께 돌려주고, 미터 계산은 코드가 한다. 이 결정은 [ADR-0003](0003-evidence-and-spatial-contracts.md)의 "추출 선은 미분류로 시작" 원칙에 대한 예외다. DXF는 기존 엔진 추출을 유지한다.

## 영향과 제약

- Muse 선은 `origin: "ai"`, `kind: "wall"`, `method: "muse"`로 표시하고 근사치 경고를 붙인다. 확인된 건축 구조나 실측 치수가 아니다.
- 축척 근거는 신뢰도 순으로 쓴다: 축척 막대·치수선(Moscone, KINTEX) → 면적 표기(LVCC 브로셔의 홀 ft²) → 표준 부스 크기 가정. 같은 등급에서는 긴 근거를 우선하고, 근거끼리 15% 넘게 다르면 경고한다. 어떤 근거를 썼는지 경고에 남긴다.
- 페이지 폭의 30%보다 짧은 길이 근거(대부분의 축척 막대)는 그 주변을 잘라 확대한 이미지로 Muse가 다시 읽는다. 이때 표시된 눈금을 모두 찍게 하고 코드가 직선으로 맞춰, 잘못 찍은 점 하나의 영향을 줄인다. 2026-11-02 측정에서 첫 판독은 기준 대비 최대 +42%였고, 확대·눈금 맞춤 뒤 KINTEX 치수선은 1% 이내, Moscone 축척 막대는 실행에 따라 ±3~11%였다.
- 계산한 가로·세로 미터도 `scaleConfirmed: false`로 둔다. 근거가 없으면 비워두고 사용자 입력을 요청한다. 축척 확인은 계속 사용자가 한다.
- 샘플 프로젝트는 도면을 4장씩 동시에 추적해 요청 예산(약 5분) 안에서 연다. 이것은 녹화 재생이 아니라 실시간 Muse 호출이다.
- 선이 너무 많아 엔진이 거부한 PDF(413)는 래스터 모드로 다시 추출한다. Muse 호출은 예산 안에서 한 번 재시도하고, 실패하면 엔진 선과 경고로 돌아간다. 실패 이유는 서버 로그에 남긴다.
- 모델 호출은 Next.js가 소유한다([ADR-0001](0001-service-boundaries.md)). Python은 렌더링과 추출만 하며 모델을 호출하지 않는다.
- 좌표 정확도가 필요해지면 Muse 선을 엔진 추출 선에 맞추거나, 미분류 선 검토 흐름으로 되돌리는 방안을 다시 결정한다.
